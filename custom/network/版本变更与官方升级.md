# 版本变更、官方客户端升级与恢复边界

本页记录可迁移的规则变更和检查方法，不包含设备日志、订阅、节点指纹、个人路径或评分版源码。公开源码同步、客户端安装、生产配置重建、节点信任更新与GitHub发布是不同事务，不能互相视为授权或完成证据。

## 官方升级前：先保留最新有效配置

1. 只读确认实际系统架构、官方App与核心版本、配置来源、脚本顺序、当前TUN/系统代理/开机自启及正常运行身份。升级App不自动授权改变这些开关或核心权限。
2. 核对当前有效的统一订阅、分流、DNS、节点与分组引用、全部手选；保留四类AI的已核实专线身份、普通主代理及用户现有出口。不得用早于撤防、政府DNS或Chrome修复的旧快照覆盖最新配置。
3. 明确区分可公开模板与仓库外私有恢复材料。模板PIN保持空占位、home按设备生成；真实订阅/凭据/节点指纹/完整配置不得提交Git。需要恢复材料时只在获授权的本机受限位置保存，不要求额外长期敏感备份。
4. 正式替换前准备不依赖当前Agent联网的恢复方法，并确认用户能执行。仅保有一个旧App副本不能恢复订阅、数据库、脚本、DNS或系统权限；没有可用恢复手段则暂停可能断网的步骤。
5. 仅采用用户认可且来源可核验的官方版本，按目标平台检查版本、签名与完整性；不为保留评分功能继续打补丁、编译定制客户端或引入旧评分仓库。客户端替换/重启可能影响连接，必须在实际授权范围内执行。

## 升级后：分别核验App与配置

- **App层：**真实启动官方App，核对界面版本与实际核心版本；正常身份运行，不恢复SGID、Guard/PF或旧浏览器限制。文件替换或CLI返回成功不等于真实App可用。
- **配置层：**回读实际运行时规则、provider、完整DNS、节点/分组引用、全部手选和相关开关；确认Chrome三个服务路由/DNS、政府DNS类别和三浏览器UDP撤销保持。不要把仅磁盘配置或固定数量当作最终运行证据。
- **网络层：**在现用代理保持开启的情况下，分别检查国内AI/Apple、四类专线AI、Google Drive/普通代理及必要DNS路径。主代理链不是服务端所见公网IP证明；共享服务和缓存命中也不证明每次请求走了预期DNS上游。
- **真实功能：**Chrome内置Gemini等需在用户允许的重启和有限操作后检查实际可见结果，不以网页测试替代原生App或浏览器功能验收。
- **刷新层：**仅刷新已确认来源，确认最新有效配置与选择仍被保留。默认离线流程遇到节点身份不符时保留有效输出；若已独立启用可信源模块，server只可由固定原HTTPS源重新认证确认，其他稳定身份变化继续拒绝。不能自动重新散列、凭同名放行或回退普通节点绕过门禁。

## 回退范围必须明确

| 操作 | 能恢复什么 | 不能声称什么 |
| --- | --- | --- |
| 回退官方App版本 | 经核验的App文件及对应启动能力 | 不等于完整配置/数据库/核心/系统权限回滚，更不证明整机掉电恢复已演练 |
| 回切配置或受控重建 | 独立验证过的订阅、分流、DNS和手选状态 | 不能用旧配置复活浏览器UDP、Guard/PF或核心SGID；文件恢复成功不等于实际联网恢复 |
| Git正常revert | 本分支公开源码变更 | 不会自动回滚客户端或设备状态；不允许改写远程历史 |
| 历史DHCP模块回退 | 仅限仍明确使用对应旧PF策略的设备上的独立授权维护 | 不是已撤防设备恢复Guard/PF的入口，也不是本次App升级回退步骤 |

本次公开层提供了[原HTTPS可信源动态入口修复](subscription/README.md)的可复用模块、合成测试及显式集成API，默认`prepare.js`仍保持离线。人工初始化的私有v2 state固定原URL哈希、除server外的稳定传输身份及policy_base；缓存只触发验证，系统curl从原HTTPS源重新认证后，仅取server更新受控基线，不采用远端本机运行策略。完整PIN继续包含server；持久私有授权账本在候选暴露前写入，兼容已发布及失败后仍可能在途的认证代，不自动裁剪。脚本/部署/统一缓存/服务输出/state成套写入，失败回退数据但保留已认证账本/已暴露脚本扩展，回退不完整明确报错，不承诺跨文件掉电原子性。公开模块/合成测试与本机生产watcher、服务和真实客户端集成由维护方分别验证；不发布实物state、真实URL/摘要/节点或生产输出，也不把`prepare.js --trust-source`包装成默认无人值守重信任入口。

正常启动、联网或局部回退不能证明历史系统死锁已经根治，不能证明所有网络、冷启动、休眠、IPv6或跨设备恢复已通过。未实际验证的层次须明确标注未验证。
