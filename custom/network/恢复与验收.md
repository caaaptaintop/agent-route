# 换机、重装与安全验收

## 恢复目标

恢复的是可审阅的分流逻辑、工具与检查方法，不是整机磁盘克隆。本仓库不备份秘密；订阅和账号由用户在新机器重新导入/登录。复制源码不等于配置已应用或防泄露验收已通过。

## 恢复顺序

1. **先不启动AI业务。**核对系统架构、客户端和真实核心版本、TUN/系统代理/IPv6现状、其他网络工具；只记录必要脱敏信息，不把上台机器的PID、UID/GID、接口名或profile ID照搬。
2. 安装来源可信的客户端及必要运行环境，先保留新机器可用网络和明确例外。导入自己的订阅，保留源组及用户选择；如果需要聚合多个订阅，另行审阅生成器，不能用本工具把不同供应商按名称混为可信来源。
3. Clone这个Fork并切到`custom/network-environment`，阅读本目录及根`docs/CLIENTS.md`、`docs/DNS-WEBRTC.md`。检查实际客户端能力，而不是假设所有版本的局部脚本顺序一样。
4. 按README核实AI节点并在仓库外生成指纹和候选。home自动取本机，额外应用路径明确配置；不同机器或更新后程序位置可能变更。可信节点摘要若不匹配，保留拒绝行为，不改成只凭名称或允许普通代理兜底。
5. 明确采用此完整规则/DNS方案及IPv6-off基线是否获准；本地例外有冲突时先解决。检查代理组引用/循环/动态成员，AI组只能可信节点或REJECT，不能含DIRECT/普通供应商。
6. 将候选应用到**隔离配置副本**，用实际Mihomo的`-t`检查，不能另起第二个TUN占用生产端口。根目录上游模板验证与定制层测试需要分别执行。
7. 正式写入前准备不依赖Agent的恢复手段：原配置在客户端可回切，或经验证的独立本机恢复；如果用户不希望生成持久敏感备份，就使用现有配置副本/客户端可回切状态。没有可靠可用的恢复手段则暂停会断网的部署；不因此绕过用户的“不做敏感备份”要求。
8. 经授权重载一次，检查**实际运行时**而非只看磁盘：规则与provider加载、主代理和AI选择、TUN、DNS、联网。订阅刷新后再检查持久性。代码不包含固定profile ID或远程控制口令。
9. Claude桌面与Code先确认认证方式再运行；API Key与订阅是不同计费途径。仅做安装/认证状态检查时不发起模型生成，不自动恢复旧账号备份。
10. 浏览器设置逐个检查：定位默认询问及旧允许列表、DoH与现有DNS策略协调；三款浏览器UDP规则实测后，再决定是否撤回原WebRTC限制。无候选、空白页、扩展安装成功都不是无泄露证明。

## 验收矩阵

每项填写`通过/失败/未验证`、设备与版本、实际证据、适用范围；缺少实际证据不标通过。采样只取域名/进程路径/规则/代理链等元数据，不导出Cookie、API Key或业务正文。

| 项目 | 方法 | 通过标准/限制 |
| --- | --- | --- |
| 静态安全 | 本目录三套JS测试；原生配置解析 | 合成测试与解析通过，只证明逻辑和语法 |
| 规则加载 | 实际controller/客户端规则页与provider | AI域名、专用进程及浏览器UDP顺序正确，数据已加载，不含意外普通/直连回退 |
| 出口分流 | 公开无认证请求与真实连接元数据 | 国内AI/Apple直连、四类专线AI走可信出口、Google Drive/其余代理随主代理；服务端出口观测与核心代理链分开记，不把core链当服务器IP证明 |
| Claude真实入口 | 桌面/Code启动、用户登录后有限操作时有界采样 | 记录实际主进程/Helper/子进程；观测到的未知目的须检查，不声称所有未来进程覆盖 |
| 已知AI DNS | 检查nameserver-policy及实际解析路径 | 指定AI解析绑AI；缓存命中不等于该次有上游查询 |
| 未知/共享域名DNS | 对新发现域名用受控唯一名和DNS路径观察 | 仅进程命中不保证AI DNS；不要为验证而修改无关共享域名全局策略 |
| WebRTC | 新建PeerConnection，国外/国内多组STUN并检查候选与核心路径；必要时TURN/音视频 | 本机公网不出现，指定UDP命中预期组；HTTP/UDP可能不同出口；测试页不能替代Claude内部场景 |
| 真实App内RTC | 仅在应用确有相关功能且用户使用时观察/测试 | 没有可控入口时写未验证，不注入任意脚本、不解除应用安全限制 |
| 定位权限 | 浏览器与系统权限页、明确授权状态 | 默认询问；不主动请求或采集精确坐标；IP仍可推测地区 |
| IPv6 | 有IPv6网络时检查AAAA/出站与物理接口接管 | 单次IPv6失败或配置`false`不证明全机防绕过；没有条件写未验证 |
| 节点故障 | 先用隔离回环替身，再经授权实际故障演练 | AI不可用时拒绝，普通代理保持可用；不关闭代理测直连基线 |
| 核心/TUN退出 | 有可靠离线恢复及独立审查后才做 | 不依赖事后Agent救援；隔离测试不冒充现网实测 |
| 冷启动/重启/休眠 | 用户在场、独立恢复可用后单独批准 | 逐项检查首包、唤醒、接口/身份变化，不由正常态结果推断 |
| 订阅刷新与回退 | 只刷新已确认目标，回读真实运行时及联网 | 恢复文件或点击成功不能单独证明已恢复；保留用户当前组选择 |

## 哪些内容不能照搬

- PF规则、系统服务root/GID绑定、设备编号、utun接口和恢复脚本必须在新系统重新核对；未经实际验证不启用。不能为恢复方便放行所有root进程。
- Safari使用共享WebKit网络进程时不能声称某条规则仅影响Safari；未获范围授权不扩大到全部WebKit应用。
- 旧浏览器整份plist、Cookie、站点授权、账号设置不批量覆盖。只对明确键做最小修改，写后在实际页面及行为中核验。
- 实际订阅和节点指纹更新与上游公开规则更新是两个过程，不能让自动同步顺便重新建立节点信任。
- 本仓库不承诺零泄露、不承诺账号安全、不提供绕过平台资格或账号政策的保证。

## 对恢复速度的真实预期

有源码和模板后，不必重新从聊天拼凑方案；但新系统权限、订阅取得、节点校验、客户端版本及真实网络仍需检查。本版本是可测试的离线恢复基础，不是已在另一台电脑验收的一键安装器。
