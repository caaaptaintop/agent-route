# macOS PF：DHCPv4 换网兼容候选

这是 Fork 下游的**独立系统防火墙适配模块**，不是 AgentRoute 流量分流规则，也不是完整防直连安装器。只生成供本机审阅的候选，不访问网络、不调用系统命令、不提权、不加载 PF、不修改代理或系统服务。

## 修复什么

常驻默认拒绝的 PF 策略如果把 DHCP 服务器固定为旧网关，换 Wi-Fi、手机热点或续租时，可能出现无线已关联、实际地址获取失败。不能简单将普通应用的 UDP 放开，也不能把“已连接”当作已取得可用地址。

本模块把**精确识别的旧两规则 DHCP 块**替换为：

```pf
pass out quick inet proto udp from any port 68 to any port 67 user 0 no state label "dhcp_roaming_out"
pass in quick inet proto udp from any port 67 to any port 68 no state label "dhcp_roaming_in"
```

- 不固定网关或接口，避免首次取址依赖已经存在的默认路由，也不只允许私网 DHCP 服务器。
- 出站限定 root socket 及 UDP 68→67；不是 configd/PID 白名单，不能声称只有某个系统进程能使用。
- 入站允许 UDP 67→68，支持目标地址尚未配置的单播 OFFER/ACK；DHCP 本身仍可能遭遇伪造回复。
- 两条规则均为 `no state`。现有 LAN、DNS 排除、核心身份授权和最终拒绝规则不由本工具调整。
- 这两条规则**不是完整 PF 主规则或锚点**；不得把 `dhcp-roaming.pf` 单独当作完整系统策略加载。

低端口权限和原生 DHCP/BPF 路径需在目标系统验证。原生客户端可能绕过部分 PF 出站 socket 计数；入站恢复、租约变为 BOUND，不等于出站 `user 0` 已命中。失败时不得直接删除 UID 条件、追加 `user unknown` 或放开任意 root 流量。

## 文件

| 文件 | 用途 |
| --- | --- |
| `prepare_dhcp.py` | 标准库离线候选工具，只读显式输入，只在仓库外创建新输出 |
| `dhcp-roaming.pf` | 与生成器一致的两条规则及边界说明，不能单独部署 |
| `test_prepare_dhcp.py` | 合成规则/文件权限/拒绝路径/写入失败测试，不读取生产配置 |

不包含真实服务器、节点、主机摘要、个人路径、运行账本、日志或备份。`user 0` 是通用 root 语义，不是从旧机器复制的任意 UID/GID。

## 离线测试

Python 3.9+，POSIX 文件接口；面向 macOS，本离线工具也可在有相应 POSIX 能力的系统上测试。未在 Windows 上验证，不修改上游工作流。

在仓库根目录运行：

```bash
python3 -B -m unittest discover -s custom/network/macos-dhcp -p 'test_*.py'
python3 -O -B -m unittest discover -s custom/network/macos-dhcp -p 'test_*.py'
```

测试仅用文档保留地址与虚构接口，明确拒绝未知旧块、重复块、源摘要不符、混入非 DHCP 规则、已有新规则标记、仓库内输入输出、软链接输入、输出覆盖和部分写入失败。测试不能证明 PF 原生语法、实际 DHCP 或任意网络可用。

## 准备本地候选

这不是用户必须手工执行的教程。由获授权的本机 Agent 根据真实设备准备路径、源快照及旧块，并保留当前可用网络。**复制仓库不是部署授权。**

1. 只读确认 DHCP 失败证据、实际接口/网关/租约状态、PF 主规则和锚点顺序、当前 TUN 与核心身份；确认确有旧服务器绑定。不能仅凭网络慢就改防火墙。
2. 在仓库外准备已核验锚点的精确快照及完整旧 DHCP 块。输入必须是普通文件；工具不读取 Keychain、不发现订阅、不扫描系统目录。
3. 显式提供源快照 SHA-256。摘要是调用者核对输入的机制，不证明来源可信，不能自动重算摘要来绕过意外修改。
4. 准备仓库外、父目录已存在且目标目录尚不存在的新输出位置。工具拒绝覆盖，目录权限 0700、文件 0600。

以下变量都是待由本机 Agent 设置的路径/摘要，不包含任何机器的真实值：

```bash
: "${SOURCE_ANCHOR:?set an absolute source snapshot outside the repository}"
: "${LEGACY_DHCP_BLOCK:?set an absolute legacy-block file outside the repository}"
: "${EXPECTED_SOURCE_SHA256:?set the explicitly reviewed source digest}"
: "${NEW_REVIEW_DIRECTORY:?set a new absolute directory outside the repository}"
python3 custom/network/macos-dhcp/prepare_dhcp.py \
  --source "$SOURCE_ANCHOR" \
  --legacy-block "$LEGACY_DHCP_BLOCK" \
  --source-sha256 "$EXPECTED_SOURCE_SHA256" \
  --output-dir "$NEW_REVIEW_DIRECTORY"
```

输出只有 `candidate.pf` 与 `review.json`，默认标记为未做原生语法检查、未部署、未验证真实网络。**候选仍包含原锚点的其他本机内容，review 也含本机摘要；两者都不得提交 Git。** 不要把原始输入/输出贴到 Issue。

支持的旧块是严格的两条规则形状（可带注释/空行），测试夹具展示其语法。接口与服务器必须在两条规则中一致；遇到宏、附加规则、其他状态策略或不同语法时拒绝，不自动猜测和放宽解析。

## 集成与回退：必须由目标设备单独落实

公开工具故意不包含旧机器的 root 安装器和可信账本，以下是审查要求，不是已实现的一键事务：

1. **先建立独立离线回退。** 获取实际部署源、系统锚点副本、规范化期望规则及安装完整性元数据的可信改前副本；权限受限、放在仓库外。恢复不得依赖公网请求或当前聊天。原有过期/警示入口不能当作可用恢复。
2. 使用目标守护现有的同一控制锁，核对主规则、所有引用、原生规则输出、文件身份与安装摘要。遇到未知修改先停，不按新内容自动重建“可信”摘要。
3. 先做目标系统原生语法检查。候选只替换已确认的 DHCP 块，其余字节、规则顺序、默认拒绝、代理/节点选择均保留；检查前置规则是否会遮蔽新例外。
4. 协调更新实际部署源、系统锚点、规范化期望以及完整性元数据的对应摘要。计划只修改已获准字段；动态启动/设备绑定不可用旧整份账本覆盖。每次写入前重查目标；用同目录临时文件、fsync、原子替换及目录同步，并记录可恢复日志。
5. 仅在获得部署授权和独立审查后替换自有锚点。不得借此重载主 PF、清空锚点、开关防火墙、增删引用、改核心权限、重启客户端或切节点。不要调用行为不明的旧 start/install/recover 入口。
6. 回读规范化 live/expected、安装摘要、主规则、引用、PF states 与核心/TUN身份。**出错时，日志或某个磁盘文件恢复失败不能阻止内核补偿**；从可信改前规则恢复自有锚点，但只覆盖仍属于本次旧/新已知版本的状态。未知外来状态不得盲覆盖。
7. 回退同样逐文件检查，保留目标机器当前有效的启动/设备绑定。回退本次 DHCP 修改和整机撤防、代理配置回切是三件事，不得互相替代。

逐文件 rename **不是多文件掉电原子事务**。极端硬中断可能造成摘要/文件失配，必须有可独立执行的本地修复；若要求掉电后自动续跑/首包 fail-closed，应另行设计、审查和验收启动恢复机制，本模块不提供该保证。

## 验收清单与限制

| 检查 | 必须区分的证据 |
| --- | --- |
| 静态候选 | 非 DHCP 字节保持、端口对/UID/顺序正确；不代表原生 PF 接受 |
| 原生 PF | 语法与规范化输出符合目标系统；不代表已部署 |
| 部署完整性 | live/expected、安装摘要、主规则/引用与核心身份保持；不代表全部流量安全 |
| DHCP | 分别观察初始 DORA、单播应答、T1/T2、实际新网络和租约发布；不能只看 Wi-Fi 已连接 |
| 权限与防直连 | 非特权具体地址绑定 UDP68 的权限错误；EADDRINUSE 不算拒绝权限证据；物理 TCP/UDP/DNS 有界负测 |
| 多接口 | Wi-Fi、USB 热点、有线网按真实可用条件逐项验收，不从接口无关语法推断全部成功 |
| 异常与回退 | 写入/加载部分失败、提交后超时、外来变更、离线回退；隔离模拟不等于真实故障演练 |

本设计曾在有限设备场景观测到自然 REBIND 恢复及新入站规则命中；这不是公开工具已跨设备部署的证据，也不证明出站 UID 路径已被观测。实际设备状态、日志、指纹和备份留在本机，不收入仓库。

不保证 IPv6-only/NAT64、认证门户、802.1X 认证失败、上游封锁代理、无公网、重启/完整休眠首包或任意网络可用。旧 LAN 权限不由 DHCP 修复自动扩大；打印机/共享服务访问需要单独确认。安全策略不能承诺全机零泄漏或账号安全。
